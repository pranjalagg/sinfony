# sinfony — Design Spec

**Date:** 2026-10-03
**Status:** Approved in brainstorming; pending written-spec review

## 1. Purpose

sinfony generates music from mathematics: functions, noise, and established
math–music relations, composed in layers. It is inspired by
[{Shan, Shui}*](https://github.com/LingDong-/shan-shui-inf), which builds
infinite landscapes from seeded noise, parametric shapes, and rule-based
placement.

Goals, in priority order:

1. **Engine.** A Python library in which a piece of music is written as layered
   math, and which produces music that sounds sensible and good, not
   "machine-generated".
2. **Composition.** People can compose music by writing and combining
   functions.
3. **Learning (aspirational).** Science students learn music and piano through
   equations they already understand. The engine's primitives are chosen to
   mirror real music theory, so what a student learns transfers to a keyboard.
   If sinfony ends up as a compelling demo rather than a learning tool, that is
   acceptable.

Long-term, the same curves could drive other media (images, data, control
signals). v1 builds only the music renderer, but keeps the core medium-agnostic.

### Success criteria

- `sinfony.tonal(seed=…)` and `sinfony.ambient(seed=…)` produce pieces that
  pass a manual listening check: phrase structure, memorable repetition,
  harmonic direction, natural dynamics.
- Every musical decision traces back to a readable function or established
  theory result.
- Edit → hear → see loop in a notebook takes seconds.
- Same seed → identical piece.

## 2. Principles (carried over from shan-shui)

1. **Seeded determinism.** A piece is a function of the seed and code, not stored data.
2. **Structure × noise.** Clean math shapes give structure. Coherent noise (1/f)
   gives life.
3. **Hierarchy by frequency.** Low-frequency curves plan form and tension.
   Mid-frequency curves shape phrases. High-frequency noise shapes individual
   notes and their performance.
4. **Rules, not placement.** Local rule functions (penalties/predicates) shape
   choices, like shan-shui's `vegetate`.
5. **Parametric everything.** Every component exposes its parameters, with
   seeded defaults.
6. **Use established theory.** Prefer known math–music relations over
   arbitrary mappings.

### Theory foundations used

| Concern | Relation |
|---|---|
| Pitch | `f = 440·2^((n−69)/12)`; pitch classes in ℤ₁₂ |
| Scales | Generated by stacking fifths (`7k mod 12`); diatonic = maximally even 7-of-12 set |
| Consonance | Plomp–Levelt / Sethares roughness from partials |
| Harmony | Functional harmony T→S→D→T as Markov chain; neo-Riemannian P/L/R on Tonnetz |
| Voice leading | Minimal total semitone motion (Tymoczko) |
| Melody | Pitch proximity, gap-fill, arch contours, regression to mean (Huron, Narmour) |
| Fluctuation | 1/f (pink) noise in pitch/loudness (Voss & Clarke 1975) |
| Rhythm | Metrical grid (Lerdahl & Jackendoff); Euclidean rhythms (Toussaint) |
| Memorability | Repetition + transformation (transpose, invert, retrograde, augment) |
| Arc | Tension curve over the piece |
| Performance | Todd phrase-arc model for tempo and dynamics |
| Timbre | Additive synthesis; piano inharmonicity `fₙ = n·f₀·√(1+B·n²)` |

## 3. Scope

**In v1:** core types, six pipeline layers, numpy synth, MIDI export, piano-roll
visual with math overlays, `tonal` and `ambient` presets, one tour notebook,
tests.

**Out of v1** (design leaves room for each): infinite streaming; sampled
piano/FluidSynth backend; image/CSV/other-media renderers; Tonnetz and
circle-of-fifths views; web UI; jazz/pop styles; equation-string or YAML
front-ends; structured curriculum.

## 4. Architecture

Hybrid model: continuous `Curve`s carry intent (shape, tension, noise).
Discrete `Events` carry music (exact pitches, rhythms, repeats). A pipeline
of layers turns curves into events. Each layer reads only the outputs of the
layers above it.

```
Plan → Harmony → Voices (+ Motifs) → Perform → Render
```

| Shan-shui | sinfony |
|---|---|
| seed / PRNG | `Rng` with per-layer child streams |
| `mountplanner` (low-frequency noise) | `Plan`: form, key, tension curve |
| mountain = cos × noise | phrase contour = arch × pink noise, quantized to scale/chord |
| `vegetate` predicates | melody rules as penalty functions |
| brush-stroke noise | performance: velocity, micro-timing, phrase arcs |
| chunked rendering | (deferred) bar-by-bar streaming |

## 5. Core types

### 5.1 `Rng` (`rng.py`)

- `Rng(seed)` wraps `numpy.random.Generator`.
- `rng.child(name: str) -> Rng`: a deterministic child stream derived from
  (parent seed, name) by stable hashing.
- Each layer uses its own child stream (`"plan"`, `"harmony"`, `"voice:melody"`,
  …). Changing one layer's code or parameters must not change the random
  draws of the other layers.

### 5.2 `Curve` (`curve.py`)

- Wraps a vectorized function `f(t: ndarray) -> ndarray`. Time `t` is in
  **beats**.
- Arithmetic: `+ - * / **` and unary `-` with curves and scalars produce
  new curves. `abs(c)` works.
- Transforms: `shift(dt)`, `stretch(k)`, `clip(lo, hi)`,
  `remap(a, b, c, d)` (linear map like shan-shui's `mapval`),
  `over(t0, t1)` (bind a normalized `[0, 1]` shape to the beat range
  `[t0, t1]`; constant outside unless stated).
- Evaluation: `c(t)` accepts a scalar or an ndarray. `c.sample(t0, t1, n)` is
  also available.
- Shapes (normalized on `[0, 1]`): `const(v)`, `sine(freq, phase)`, `arch()`
  (`sin(πu)`), `ramp()`, `step(edges, values)`, `piecewise(points)`.
- Noise (seeded via `Rng`): `pink(rng, octaves=…)`, which is fractal value/Perlin
  noise with amplitude falloff 0.5 per octave and approximately 1/f
  spectrum; `white(rng)`; `brown(rng)`. Noise output is in roughly `[-1, 1]`
  and is deterministic for a given `Rng`.
- `c.show()` plots the curve.

### 5.3 `Note` / `Events` (`events.py`)

- `Note(onset: float, dur: float, pitch: int, vel: float, voice: str)` is a
  frozen dataclass. `onset` and `dur` are in beats, `pitch` is a MIDI number,
  and `vel` is in `[0, 1]`.
- `Events` is an immutable sequence of `Note`s sorted by `(onset, pitch)`.
- Operations (the musical group actions):
  - `transpose(k)` (chromatic)
  - `transpose_diatonic(k, scale)`
  - `invert(axis)`
  - `retrograde()` (reverse in time within its span)
  - `augment(k)` (scale durations and onsets)
  - `shift(dt)`
  - `filter(pred)`
  - `map(fn)`
  - `a + b` (concatenate: `b` starts at the end of `a`'s span)
  - `a | b` (overlay)
- `span` is the `(start, end)` in beats. `by_voice()` splits events into one
  group per voice.

### 5.4 `theory` (`theory.py`)

- `freq(n)`, `pc(n) = n mod 12`.
- `Scale(root: int, pcs: frozenset[int])`:
  - `Scale.generated(gen=7, n=7, root)`: stack `n` steps of the generator,
    starting from the step that yields the standard mode (`generated(7,7)` is
    major, `generated(7,5)` is major pentatonic).
  - Presets: `major`, `minor`, and the modes `dorian`, `phrygian`, `lydian`,
    `mixolydian`, `aeolian`, `locrian`; plus `pentatonic`.
  - Methods: `degree(i) -> MIDI` (handles octaves and negative degrees),
    `degree_of(pitch)`, `nearest(pitch)`, `contains(pitch)`.
- `Chord(root: int, pcs: frozenset[int], label: str)`:
  - `triad(scale, degree)` and `seventh(scale, degree)`.
  - Roman-numeral parsing for `Fixed` progressions (`"I"`, `"vi"`, `"V7"`,
    `"V/V"`).
  - `pitches(lo, hi)`.
  - Neo-Riemannian `P`, `L`, `R`, defined on major and minor triads. Each is an
    involution.
- `voice_lead(voicing: list[int], target: Chord, lo, hi) -> list[int]`: the
  voicing of `target` with the same number of voices that minimizes total
  absolute semitone motion. It is brute force over small candidate sets, with
  ties broken toward contrary motion.
- `roughness(pitches, partials=6) -> float`: Sethares dissonance using
  Plomp–Levelt curves over harmonic partials.

## 6. Pipeline layers

### 6.1 Plan (`plan.py`)

- `Form(spec: str, bars: int | list[int], meter=(4, 4))`. The spec is a list of
  section labels separated by spaces, for example `"A A' B A"`. It produces
  `Section(label, base_label, start_beat, end_beat)`; `A'` has base label `A`.
- `Plan(seed, key: Scale, form: Form, tempo: float | Curve, tension: Curve | None)`.
- Default tension: a piecewise curve that rises across sections, peaks around
  0.6–0.7 of the total length, and resolves to low at the end. Faint pink
  noise (amplitude ≈ 0.05) is added. The result is clipped to `[0, 1]`.
- Optional key per section. `Plan.section_key(section)` returns the key for a
  section. B sections may modulate to the dominant or relative key, chosen
  by the plan's Rng and weighted by tension.

### 6.2 Harmony (`harmony.py`)

- Output: `ChordTrack`, a list of `ChordSpan(onset, dur, chord, function)`.
- Strategy interface: `strategy.generate(plan, rng) -> ChordTrack`.
- `Functional(rhythm: Curve | None)`:
  - A Markov chain over harmonic functions T, S, and D, mapped to scale
    degrees (T: I, vi; S: IV, ii; D: V, vii°).
  - Tension biases the transition weights toward D and toward secondary
    dominants.
  - Cadences are forced: section ends get an authentic cadence (V→I); the
    middle of an 8-bar period gets a half cadence (ending on V).
  - Harmonic rhythm is 1 chord per bar by default and 2 per bar approaching
    cadences.
- `TonnetzWalk(rate: Curve | None)`: a random walk of P, L, and R moves.
  Move probability rises with tension. The walk is constrained to chords whose
  pitch classes fit the plan's scale where possible. Chords change every 2–4
  bars.
- `Fixed(numerals: list[str], per_bar=1)`: a user-specified progression,
  repeated across the form.
- **Repetition:** sections with the same base label reuse the same chord
  track. A primed section (`A'`) may alter its final cadence.

### 6.3 Voices (`voices.py`, `rules.py`)

- `Voice(name, role, register: (lo, hi), rhythm, pitch, rules)`.
- Rhythm generators produce onsets and durations from `MeterGrid`.
  - `MeterGrid(meter)`: beat strength comes from the metric hierarchy (downbeat >
    mid-bar > beats > subdivisions).
  - `euclid(k, n, rotate=0)`: Bjorklund's algorithm.
  - `density(curve)`: onset probability = `density(t) × strength(t)`, sampled
    with the voice's Rng.
  - `pattern(...)`: fixed patterns (block, arpeggio, Alberti).
- Melody pitch selection:
  1. The contour `Curve` gives a target pitch at each onset.
  2. Candidates are chord tones on strong beats and scale tones on weak beats,
     within the register.
  3. `score = |candidate − target| + Σ rule penalties`.
  4. Choose the argmin, or sample with `softmax(−score / temperature)`.
- A rule is a function `(ctx, candidate) -> float` penalty. `ctx` holds the
  previous notes, the current chord, the scale, the beat strength, and the
  section position. v1 rules:
  - `step_bias(w)`: penalize leaps.
  - `gap_fill(w)`: after a leap of more than 4 semitones, penalize continuing
    in the same direction.
  - `range_limit(lo, hi)`.
  - `avoid_repeat(w, n)`.
  - `resolve_leading_tone(w)`.
  - `end_on_tonic(w)`: applies at the final note of a section ending in an
    authentic cadence.
- Bass: the chord root by default. Inversions are allowed when they reduce
  bass motion.
- Accompaniment: the chord voiced through `voice_lead` from the previous
  voicing, then laid out by the rhythm pattern.

### 6.4 Motifs (`motif.py`)

- For each base label, generate a 1–2 bar motif with the melody machinery.
- Develop the motif into an 8-bar period:
  - Antecedent: the motif, then a sequence (diatonic transpose), ending on the
    half cadence.
  - Consequent: the motif again, then a variation (inversion or
    augmentation), ending on the authentic cadence.
  - The variation is chosen by Rng.
- Re-quantize transformed notes to the current chord and scale, so harmony
  wins over literal transformation.
- The motif layer is optional per voice. `tonal` uses it for its melody.
  `ambient` instead gets its repetition from reused sections and phasing
  loops.
- A repeated label reuses its period verbatim, with only performance-level
  variation. A primed label (`A'`) applies one stronger transform (for example
  ornamentation, an octave shift, or a changed cadence).

### 6.5 Perform (`perform.py`)

- Input: `Events` and the `Plan`. Output: `Events` with performance velocities
  and timings, plus a `tempo: Curve` in BPM.
- Todd phrase arcs: per phrase, tempo and loudness follow a parabola, with a
  peak mid-phrase and a lower start and end. A final ritardando covers the
  last 2 bars.
- `vel = base × accent(strength) × arc(t) × (0.7 + 0.3·tension(t))`, clipped
  to `[0.05, 1]`.
- Micro-timing: onset jitter of a few milliseconds from pink noise. The
  amplitude is a preset parameter.

### 6.6 Piece (`piece.py`)

- `Piece(plan, harmony, voices, perform, synth=…)` runs the layers in order,
  lazily and cached.
- Exposes `.plan`, `.chords`, `.events`, `.tempo`.
- Methods: `.play()`, `.show(save=None)`, `.save_wav(path)`,
  `.save_midi(path)`, `.audio()` (returns an ndarray).
- Each layer output can be inspected on its own (for example
  `piece.chords.show()`).

## 7. Rendering

All renderers follow the interface `render(events, tempo, **opts)`.

### 7.1 Synth (`render/synth.py`)

- Sample rate 44.1 kHz, float32. Beats are converted to seconds by
  integrating `60 / tempo(t)`.
- An `Instrument` is a list of partials `(ratio, amp, decay)` plus an
  envelope. Piano-like presets apply inharmonicity `fₙ = n·f₀·√(1+B·n²)` and
  add a short filtered-noise hammer burst.
- Presets: `epiano`, `pad` (slow attack, detuned partials), `bell`, `sine`.
- Reverb: FFT convolution with a synthetic impulse response (exponentially
  decaying noise). Parameters: length and wet/dry mix.
- Master chain: sum → reverb → peak normalize → `tanh` soft clip.

### 7.2 Playback (`render/play.py`)

- In Jupyter, show an inline `IPython.display.Audio`.
- Otherwise, play through `sounddevice` if it is installed. If not, write a
  temporary WAV file and print its path.

### 7.3 Visuals (`render/viz.py`)

matplotlib, shown inline or saved to SVG/PNG.

- Piano roll: x = beats, y = pitch, bars colored by voice, alpha = velocity.
- Overlays:
  - the melody contour target curve
  - a tension strip below the roll
  - chord labels on top (Roman numeral plus pitch-class set)
  - shaded section bands
  - a keyboard strip with the scale's pitch classes highlighted

### 7.4 MIDI (`render/midi.py`)

- `mido`, one track per voice.
- Velocity maps to `round(1 + 126·vel)`.
- The tempo curve is written as tempo-change meta events, one per beat.

## 8. Presets (`presets.py`)

A preset is a plain function `(seed, **overrides) -> Piece` that uses only the
public API. Any constructor argument can be overridden.

### `tonal` (~1.5 min)

- Major or minor, chosen by seed. Tempo 72–100. Meter 4/4 or 3/4.
- Form `A A' B A`, 8 bars per section. B may modulate.
- Harmony: `Functional`.
- Voices:
  - Melody: C4–C6. Contour = phrase arch + 0.25·pink. Rules: step_bias,
    gap_fill, resolve_leading_tone, end_on_tonic.
  - Bass: C2–C4.
  - Accompaniment: Alberti in A sections, block chords in B.
- Motifs: period structure.
- Perform: Todd arcs and a final ritardando.
- Synth: `epiano` with a short reverb.

### `ambient` (~3 min)

- Scale: a mode (dorian, lydian, or aeolian) or pentatonic. Tempo 50–66.
- Form `A B A' C A`, with long sections.
- Harmony: `TonnetzWalk`, a chord every 2–4 bars.
- Voices:
  - Pad: sustained chord tones, voice-led.
  - Sparse melody: low `density` curve, pentatonic subset.
  - Two phasing loops: Euclidean patterns of coprime lengths, for example
    E(3,8) and E(5,13). They realign only every lcm(8, 13) = 104 steps.
- Perform: soft dynamics, wider timing jitter.
- Synth: `pad` with a long reverb.

## 9. Error handling

- Invalid user input raises a `ValueError` with a clear message: unknown Roman
  numeral, empty form, register with `lo >= hi`, or a curve evaluating to
  NaN or inf at sampled points.
- If melody selection finds no candidate in register, it widens the register
  by one octave and emits a `warnings.warn`; the piece never fails silently.
- Renderers validate that audio is finite before normalizing.

## 10. Testing

pytest, with one test module per source module.

- **Theory facts:**
  - `freq(69) == 440`.
  - `Scale.generated(7, 7)` equals the major scale; `generated(7, 5)` equals
    the pentatonic scale.
  - P, L, and R are involutions.
  - `voice_lead` is minimal on hand-checked cases.
  - `roughness` of a perfect fifth is less than that of a minor second.
- **Group laws:**
  - `transpose(a).transpose(b) == transpose(a + b)`.
  - `retrograde` and `invert` applied twice give the identity.
  - `augment(k).augment(1/k)` gives the identity.
- **Noise:** the log–log spectral slope of `pink` is ≈ −1 (tolerance ±0.3).
  Noise is deterministic per Rng.
- **Determinism:** the same seed gives identical `Events`. Changing melody
  parameters leaves `ChordTrack` unchanged (layer isolation).
- **Musical invariants, over seeds 0–49 for both presets:**
  - Melody pitches stay in the section's scale (except permitted chromatic
    tones from secondary dominants).
  - Strong-beat melody notes are chord tones.
  - Tonal pieces end on the tonic chord, with the melody on the tonic.
  - Registers are respected.
  - `tonal` only: at least 60% of melodic intervals are steps
    (≤ 2 semitones).
  - Repeated base labels share pitch material.
- **Render:**
  - Audio is finite and within `[−1, 1]`.
  - Audio duration matches the tempo integration within 1%.
  - A MIDI round trip preserves the note count.
  - The visuals render headless with the Agg backend.
- **Manual:** a listening check per preset before calling v1 done.
